# 디자인 가이드: 중온 아스팔트 외부사업 온실가스 산정 웹앱

## 1. 디자인 목표

아스팔트 제조공장의 품질관리 실장 또는 관리부 실장이 복잡한 방법론을 몰라도 현재 단계와 필요한 입력값을 이해하고, 실수 없이 온실가스 산정 결과를 확인할 수 있게 한다.

## 2. 핵심 디자인 원칙

1. 예쁜 화면보다 업무 완료와 입력 오류 방지를 우선한다.
2. 한 화면에서는 하나의 주요 작업에 집중하게 한다.
3. 전문용어보다 현장에서 사용하는 쉬운 표현을 먼저 보여준다.
4. 숫자에는 반드시 단위를 함께 표시한다.
5. 계산 결과뿐 아니라 계산에 사용한 근거도 확인할 수 있게 한다.
6. 색상만으로 상태를 구분하지 않고 아이콘과 문구를 함께 사용한다.
7. 필수 입력, 선택 입력, 확인 필요 항목을 명확히 구분한다.

## 3. 참고 화면에서 가져갈 방향

- 색: 흰색과 연한 회색을 바탕으로 사용하고, 녹색은 메뉴·현재 단계·정상 상태처럼 중요한 부분에만 제한적으로 사용한다.
- 여백: 입력 영역과 결과 영역을 카드로 구분하고 카드 안팎에 일정한 여백을 두어 답답하지 않게 구성한다.
- 순서: 좌측에는 전체 단계를 배치하고 본문은 현재 상태 요약 → 해야 할 작업 → 입력자료 목록 → 도움말 순서로 구성한다.
- 문구: 전문용어만 표시하지 말고 무엇을 입력해야 하는지와 입력하면 어떤 결과가 나오는지를 짧고 직접적으로 설명한다.

## 4. 전체 화면 구조

### 4.1 상단 영역

상단에는 현재 사업장명, 산정기간, 방법론 버전을 표시한다.

예시:

```text
○○아스콘 | 2026년 산정 | 06A-001-Ver01
```

### 4.2 좌측 메뉴

좌측 메뉴에는 전체 업무 단계를 실제 진행 순서대로 표시한다.

1. 사업장 설정
2. 방법론 확인
3. 산정조건 설정
4. 베이스라인 자료
5. 월별 활동자료
6. 입력 검토
7. 산정 결과

현재 단계는 녹색 배경 또는 녹색 선으로 강조하고, 완료된 단계에는 `완료` 문구 또는 체크 아이콘을 표시한다.

### 4.3 본문 영역

본문 상단에는 화면 제목과 한 줄 설명을 표시하고, 그 아래에 현재 화면의 주요 작업을 배치한다.

본문 하단에는 사용자가 막혔을 때 참고할 수 있는 도움말을 제공한다.

예시:

```text
이 값은 어디서 확인하나요?
연료 사용량은 유량계 측정일지 또는 연료 구매자료에서 확인할 수 있습니다.
```

## 5. 첫 화면 구성

첫 화면은 전체 데이터를 보여주는 화면이 아니라 사용자가 지금 해야 할 일을 알려주는 화면으로 구성한다.

### 5.1 상태 요약 카드

다음 네 가지 항목을 우선 표시한다.

| 카드 | 표시 내용 |
|---|---|
| 입력 완료 | 입력이 완료된 월의 개수 |
| 확인 필요 | 증빙 또는 입력 확인이 필요한 월의 개수 |
| 산정 제외 | 온도·품질조건으로 제외된 월 또는 자료의 개수 |
| 예상 감축량 | 현재 입력값으로 계산한 온실가스 감축량 |

### 5.2 다음 작업

상태 카드 아래에는 사용자가 다음에 해야 할 작업을 한 가지로 안내한다.

예시:

```text
3월 전력 사용량 증빙을 등록해주세요.
```

주요 버튼:

```text
3월 활동자료 확인하기
```

### 5.3 최근 활동자료

최근 입력한 월별 활동자료를 표로 보여준다.

| 대상 월 | 생산량 | 연료 사용량 | 전력 사용량 | 상태 |
|---|---:|---:|---:|---|
| 2026년 3월 | 1,200 t | 8,500 L | 12,400 kWh | 확인 필요 |

## 6. 입력 화면 디자인

### 6.1 입력 항목 배치

관련된 항목끼리 한 카드에 묶는다.

- 생산정보: 대상 월, 중온 아스팔트 생산량
- 에너지정보: 연료 종류, 연료 사용량, 전력 사용량
- 적합성정보: 배합 생산온도, 품질 등급, 품질 적합 여부
- 증빙정보: 계량기 사진, 측정일지, 고지서, 성적서

### 6.2 입력 필드

- 항목명은 입력란 위에 표시한다.
- 필수 항목에는 `필수` 문구를 표시한다.
- 단위는 입력란 오른쪽에 고정하여 표시한다.
- 입력 예시는 입력란 안에 흐린 문구로 표시한다.
- 도움말은 꼭 필요한 항목에만 제공한다.

예시:

```text
중온 아스팔트 생산량  필수
[ 1,200               ] t-아스콘
```

### 6.3 주요 버튼

한 화면에서 가장 중요한 버튼 하나만 녹색으로 강조한다.

- 주요 버튼: 저장하고 다음으로
- 보조 버튼: 이전
- 위험 버튼: 삭제

`저장`, `확인`, `다음`처럼 의미가 겹치는 버튼을 한 화면에 여러 개 배치하지 않는다.

## 7. 결과 화면 디자인

### 7.1 결과 요약

결과는 다음 순서로 표시한다.

1. 온실가스 감축량
2. 베이스라인 배출량
3. 사업 배출량
4. 누출량
5. 인정된 중온 아스팔트 생산량

가장 중요한 온실가스 감축량을 가장 크게 표시한다.

예시:

```text
온실가스 감축량
12.4 tCO₂-eq/년
```

### 7.2 계산 근거

기본 화면에서는 한글 명칭을 먼저 표시하고 방법론 기호는 보조정보로 제공한다.

예시:

```text
베이스라인 배출량 (BE)
사업 배출량 (PE)
누출량 (LE)
온실가스 감축량 (ER)
```

상세영역에서는 입력값, 적용계수, 단위변환, 계산식을 확인할 수 있게 한다.

### 7.3 산정 제외자료

산정에서 제외된 자료는 결과 아래에 별도로 표시한다.

예시:

```text
4월 생산자료는 배합 생산온도가 142℃로 입력되어 산정에서 제외되었습니다.
```

## 8. 상태 표현

| 상태 | 색상 | 아이콘 또는 문구 | 의미 |
|---|---|---|---|
| 완료·정상 | 녹색 | 체크 + 완료 | 입력과 증빙이 준비됨 |
| 확인 필요 | 주황색 | 느낌표 + 확인 필요 | 입력 또는 증빙 확인 필요 |
| 산정 제외 | 빨간색 | 제외 + 산정 제외 | 방법론 조건을 충족하지 않음 |
| 미입력 | 회색 | 미입력 | 아직 입력하지 않음 |

색각 차이가 있는 사용자도 이해할 수 있도록 색상만 사용하지 않는다.

## 9. 색상 가이드

| 역할 | 권장 색상 | 사용 위치 |
|---|---|---|
| 주요 녹색 | `#08775B` | 주요 버튼, 현재 메뉴, 정상 상태 |
| 진한 녹색 | `#075C48` | 제목, 강조 문구 |
| 연한 녹색 | `#E7F4EE` | 선택된 메뉴, 안내 배경 |
| 기본 배경 | `#F4F8F6` | 전체 페이지 배경 |
| 카드 배경 | `#FFFFFF` | 입력 및 결과 카드 |
| 기본 글자 | `#16251F` | 본문과 제목 |
| 보조 글자 | `#5E6F67` | 설명과 도움말 |
| 확인 필요 | `#A85F00` | 경고와 확인 필요 상태 |
| 산정 제외 | `#A33D3D` | 오류와 제외 상태 |

## 10. 여백과 크기 가이드

- 페이지 본문 좌우 여백: 32~48px
- 카드 사이 간격: 16~24px
- 카드 내부 여백: 20~24px
- 제목과 설명 사이: 8px
- 설명과 입력영역 사이: 20~24px
- 입력란 높이: 최소 44px
- 주요 버튼 높이: 최소 44px
- 본문 글자: 14~16px
- 화면 제목: 28~32px
- 카드 제목: 18~20px

같은 역할의 요소는 모든 화면에서 같은 여백과 크기를 사용한다.

## 11. 문구 작성 원칙

- 사용자가 해야 할 행동을 문장 앞에 쓴다.
- 오류의 원인과 해결방법을 함께 알려준다.
- 전문용어는 한글 명칭 뒤에 방법론 기호를 붙인다.
- 불필요하게 긴 안내문은 펼쳐보기 영역으로 분리한다.
- 버튼은 실행 결과가 예상되는 문구를 사용한다.

좋은 예:

```text
전력 사용량 증빙을 등록해주세요.
배합 생산온도가 140℃를 초과하여 산정에서 제외됩니다.
활동자료를 저장하고 결과 확인으로 이동합니다.
```

피할 예:

```text
오류가 발생했습니다.
처리할 수 없습니다.
확인
다음
```

## 12. 할 것

- 상단에 현재 사업장과 산정기간을 항상 표시한다.
- 좌측 메뉴에 업무 단계를 실제 진행 순서대로 표시한다.
- 현재 단계와 완료 단계를 명확하게 구분한다.
- 첫 화면에는 입력 완료, 확인 필요, 산정 제외 및 예상 감축량을 요약한다.
- 사업장, 베이스라인, 월별 활동자료, 증빙을 별도 화면 또는 영역으로 구분한다.
- 모든 숫자 입력값에 단위를 함께 표시한다.
- 필수 입력과 선택 입력을 구분한다.
- 정상, 확인 필요, 산정 제외 상태를 색상과 문구로 함께 표시한다.
- 계산 결과와 계산 근거를 연결한다.
- 주요 버튼은 화면마다 하나만 강조한다.
- 사용자가 막히기 쉬운 항목에 짧은 도움말을 제공한다.
- 표의 열이 많아지면 가로 스크롤보다 중요도가 낮은 정보를 상세화면으로 분리한다.

## 13. 하지 않을 것

- 참고 화면의 색상과 구성을 그대로 복사하지 않는다.
- 모든 기능과 숫자를 첫 화면에 한꺼번에 보여주지 않는다.
- 초록색을 모든 제목, 숫자, 표와 버튼에 사용하지 않는다.
- 색상만으로 상태를 구분하지 않는다.
- 방법론 기호를 사용자 화면의 중심 문구로 사용하지 않는다.
- 사업장 설정과 월별 활동자료 입력을 한 화면에 모두 배치하지 않는다.
- 필수 입력과 선택 입력을 같은 모양으로 표시하지 않는다.
- 온도 또는 품질기준을 충족하지 않은 자료를 정상 결과처럼 표시하지 않는다.
- 오류 원인을 설명하지 않고 계산만 차단하지 않는다.
- 한 화면에 동일한 강도의 버튼을 여러 개 배치하지 않는다.
- 로그인, 결재, 권한관리 또는 IoT 자동연동 화면을 추가하지 않는다.
- 장식 목적의 그래프를 추가하지 않는다.

## 14. 화면별 우선순위

| 화면 | 가장 중요한 정보 | 가장 중요한 행동 |
|---|---|---|
| 첫 화면 | 전체 진행상태와 다음 작업 | 미완료 항목 확인 |
| 사업장 설정 | 사업장과 산정기간 | 기본정보 저장 |
| 방법론 확인 | 적용조건 충족 여부 | 조건 확인 완료 |
| 산정조건 설정 | 연료와 적용계수 | 산정조건 저장 |
| 베이스라인 자료 | 사업 전 생산량·연료·전력 | 베이스라인 입력 |
| 월별 활동자료 | 생산량·에너지·온도·품질 | 월별 자료 저장 |
| 입력 검토 | 누락과 산정 제외 사유 | 오류 수정 |
| 산정 결과 | 온실가스 감축량과 계산 근거 | 결과 확인 |

## 15. 디자인 완료 기준

처음 사용하는 사람이 별도 교육 없이 현재 단계, 입력할 값, 입력 단위, 오류 원인, 다음 행동 및 온실가스 산정 결과를 화면에서 이해할 수 있으면 디자인이 완료된 것으로 본다.
